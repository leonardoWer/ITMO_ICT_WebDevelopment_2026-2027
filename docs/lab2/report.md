# Лабораторная работа №2. Разработка веб-приложения на Django

## Введение и постановка задачи
В рамках лабораторной работы было реализовано веб-приложение на фреймворке Django. Темой индивидуального варианта стал баскетбольный чемпионат по образцу Западной конференции НБА. Сайт представляет собой табло с матчами, командами и игроками. Пользователи могут регистрироваться на сайте, оставлять свои прогнозы на исход предстоящих матчей и писать отзывы с рейтингом к прошедшим играм. Администратор имеет расширенные права и может редактировать счет и статус матча прямо в клиентской части сайта.

## Настройка проекта и базы данных
Работа началась с создания виртуального окружения и установки необходимых пакетов, таких как Django и драйвер psycopg2-binary для работы с PostgreSQL. Был создан проект config и приложение basketball. В файле настроек settings.py приложение было добавлено в список INSTALLED_APPS. В качестве базы данных использовалась PostgreSQL, параметры подключения к которой были прописаны в словаре DATABASES.

Так как в задании требовалось реализовать регистрацию и разграничение прав, было принято решение расширить стандартную модель пользователя. Для этого в settings.py была добавлена строка AUTH_USER_MODEL, указывающая на кастомную модель CustomUser, которую мы создали на основе AbstractUser. Это позволяет нам хранить дополнительные данные о пользователе, например его отображаемое имя.

## Проектирование моделей данных
Структура базы данных была продумана заранее. Основными сущностями стали команды, игроки, матчи, а также прогнозы и комментарии пользователей. Модель Team хранит название и город команды. Модель Player связана с командой через внешний ключ (ForeignKey) и содержит информацию об игроке, его амплуа и игровом номере.

Для матчей была создана модель Match. В ней есть два внешних ключа на модель Team, так как в одном матче участвуют хозяева и гости. Чтобы Django не путался, для этих полей были заданы разные параметры related_name. Также матч имеет дату, место проведения, счет и статус (предстоящий или завершенный).

Модель Prediction позволяет авторизованному пользователю оставить прогноз на счет матча. А модель Comment хранит текстовые отзывы и оценку от одного до десяти. Для обеих моделей настроена связь с пользователем и матчем.

Пример описания модели матча:
```python
class Match(models.Model):
    STATUS_CHOICES = [
        ('upcoming', 'Предстоящий'),
        ('finished', 'Завершенный'),
    ]
    home_team = models.ForeignKey(Team, on_delete=models.CASCADE, related_name='home_matches')
    away_team = models.ForeignKey(Team, on_delete=models.CASCADE, related_name='away_matches')
    date = models.DateTimeField()
    status = models.CharField(max_length=10, choices=STATUS_CHOICES, default='upcoming')
    home_score = models.PositiveIntegerField(default=0)
    away_score = models.PositiveIntegerField(default=0)
```

После описания моделей были выполнены миграции, и все таблицы успешно создались в базе данных PostgreSQL

## Контроллеры и архитектура представлений
В процессе работы использовались как представления на основе классов (CBV), так и на основе функций (FBV). Для вывода списка команд и матчей использовался класс ListView. Он автоматически делает запрос к базе данных и передает список объектов в шаблон. Для просмотра детальной информации о команде использовался DetailView.

Для главной страницы с матчами был написан класс BasketballMatchListView. В нем реализована фильтрация и пагинация. Метод get_queryset позволяет фильтровать матчи по их статусу или искать по названию команды через GET-запрос. Также настроена пагинация по восемь элементов на страницу.

Страница отдельного матча обрабатывается классом MatchDetailView на основе базового класса View. В методе get мы собираем контекст, включая прогноз текущего пользователя и список комментариев. В методе post обрабатываются сразу три формы: форма прогноза, форма комментария и скрытая форма администратора для обновления статуса матча.

Для регистрации пользователей была написана функция register. Она использует кастомную форму, создает нового пользователя, автоматически авторизует его и перенаправляет на главную страницу.

## Шаблоны и пользовательский интерфейс
Для визуальной части использовался CSS-фреймворк Tailwind CSS, подключенный через CDN. Дизайн выполнен в минималистичной и спортивной эстетике. Используется темный фон, строгие шрифты и красные акценты, характерные для баскетбольной тематики.

Все шаблоны расположены в папке templates/basketball. Базовые страницы (логин, регистрация, списки) имеют общую навигационную панель. Активная вкладка в меню подсвечивается красной линией. На страницах матчей реализована удобная форма поиска и фильтрации, а также кнопки переключения страниц пагинации.

Разграничение прав реализовано через проверку user.is_staff прямо в HTML-шаблоне. Если заходит администратор, на странице матча появляется специальная панель с полями для изменения статуса игры и итогового счета. Обычные пользователи видят только форму для своих прогнозов и отзывов.

## Тестирование и наполнение данными
Для проверки работы сайта база данных была наполнена реальными командами Западной конференции НБА, такими как Golden State Warriors, Los Angeles Lakers и другие. Матчи были добавлены с актуальными датами и статусами.

В ходе тестирования было проверено, что неавторизованный пользователь не может оставлять прогнозы и комментарии. После регистрации появляется возможность делать прогнозы. При повторной отправке формы прогноза он обновляется, а не создается дубликат. Администратор успешно меняет счет, после чего матч переходит в статус завершенного и счет отображается на табло.

## Инструкция по локальному запуску
Для того чтобы запустить проект на другом компьютере, необходимо выполнить несколько шагов. Сначала нужно клонировать репозиторий и перейти в папку laboratory_work_2. Затем создать виртуальное окружение командой python -m venv .venv и активировать его. После этого установить зависимости командой pip install -r requirements.txt.

Далее необходимо настроить базу данных PostgreSQL. Нужно создать пустую базу и прописать ее параметры в файле config/settings.py. После настройки базы следует применить миграции командой python manage.py migrate. Для доступа к админке можно создать суперпользователя командой python manage.py createsuperuser. Запускается сервер командой python manage.py runserver.
